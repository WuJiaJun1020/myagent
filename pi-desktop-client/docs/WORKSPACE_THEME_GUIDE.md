# Agent 工作区主题接入与验收

## 范围

P4 提供简约灰、暖砂、雾蓝三套配色，每套包含浅色和深色。模式独立选择浅色、深色或跟随系统；强调色独立选择随主题、蓝色、绿色或紫色。现有字体、字号和动画设置继续使用。配色主题目前仅覆盖 Agent 工作区；智慧面试与知识工坊的完整迁移属于 P5、P6。

## 唯一配色入口

`src/renderer/lib/workspace-theme.ts` 提供 `getThemeTokens`、`themeStyle`、`workspaceThemeCss`。新增主题必须在此定义，不在组件、终端或预览里复制颜色。

- `theme-bootstrap.ts` 在 React 挂载前读取已有设置并注入主题规则，避免首屏与已保存偏好不一致。
- `AppProviders` 监听设置及系统明暗变化，通过 HTML 的 `data-theme`、`data-palette`、`data-accent` 应用外观。
- `settings-store.ts` 沿用 `pi-desktop-settings` 存储。新增字段为 `palette`、`accent`；老用户缺少字段时补默认值，不覆盖已有模式、字体、字号或模型偏好。
- `terminal-theme.ts` 从同一配色取得背景、前景、光标与选区。切换时只更新 xterm 的 `options.theme`，不重建终端、不关闭 PTY；ANSI 语义色继续区分命令输出。
- `WorkspaceThemePreview` 使用 `themeStyle` 绘制侧栏、问答、代码与输入框的小型预览，与实际主题同源。

## 页面与组件规则

| 用途 | 使用方式 |
| --- | --- |
| 主页面、侧栏、卡片、浮层 | `--bg-app`、`--bg-sidebar`、`--bg-panel`、`--bg-elevated` |
| 悬浮、选中、选中后悬浮 | `--bg-hover`、`--bg-selected`、`--bg-selected-hover` |
| 正文、次要说明、辅助文字 | `--text`、`--text-soft`、`--text-muted` |
| 操作与键盘焦点 | `--accent`、`--accent-soft`、`--accent-ink` |
| 普通边界、强调边界 | `--border`、`--border-strong` |
| 成功、警告、失败 | `--green`、`--amber`、`--red` 及相应 soft/border 变量，并保留文字或图标 |
| 悬浮提示、下拉菜单 | `HoverHint` / `HintButton` 与 `styles/overlays.css`，不使用原生 title 提示 |

页面沿用“侧栏＋页头＋主内容＋按需展开详情”的结构。表单沿用 `SettingsGroup` / `SettingsRow`，设置内容宽度和间距由公共样式控制。不要用减小字号解决拥挤；输入框工具栏保持单行，审查保留左右结构。新增主题不能触发业务 Store 重置或在 React 根节点使用主题值作为 key。

动画关闭同时控制 MotionConfig 与 CSS 动画/过渡，键盘焦点和操作反馈仍保留。主题单选卡支持方向键、Home、End 与 Tab；下拉选项支持原生键盘操作。

## 可运行设计样板

执行 `npm run preview:workspace`，打开生成的 `docs/AGENT_WORKSPACE_PREVIEW.html`。顶部可以切换三种主题、明暗、会话、代码审查、文件/终端与窄布局。样板使用真实展示组件和虚构数据，不调用模型、不读写实际项目文件；外观设置区域为静态展示，实际保存行为在客户端设置中验证。

生成文件不提交 Git；脚本、主题数据和公共样式是样板来源。功能回归不能以样板替代。

## 验收要求

1. 六种主题组合检查侧栏、对话、设置、文件、Diff、终端、资源、提示和选项；再检查强调色、错误、禁用及焦点。
2. 浅色、深色均验证悬浮可见且与选中可区分；检查窄窗口与较大字号，避免内容遮挡。
3. 切换主题前后核对未保存编辑、会话草稿、滚动位置与终端进程；检查保存恢复及系统模式的实时变化。
4. `workspace-theme.test.ts` 检查 24 种配色/模式/强调色组合的关键文字对比度和终端配色一致性；`settings-store.test.ts` 检查旧设置保留、持久化恢复及无效新字段回退。
5. 运行类型检查、相关测试、生产构建与渲染资源检查。记录实际验证范围，不用静态组件截图宣称真实 PTY、文件保存或模型流程已经通过。

## P4 收尾验收结果（2026-09-26）

运行 `npm run verify:themes` 可重做验收。程序用 Electron 38 的真实 `WorkspaceApplication`、状态 Store、设置页、输入框、编辑器、代码审查及 xterm；会话与文件为虚构数据，配色使用生产构建 CSS。独立 userData 与 PTY 位于 `.cache/theme-acceptance`，不连接模型，不读写用户会话，不保存测试编辑。

通过的 13 项专项检查：

- 对话滚动位置在打开设置、切换主题、关闭设置后保持。
- 编辑器未保存文本保持，编辑器 DOM 未因主题切换重建。
- 输入框草稿保持，xterm DOM 保持。
- 通过 Electron `nativeTheme.themeSource` 改变本测试进程的原生明暗来源，验证真实 `matchMedia` change 事件；跟随系统立即响应，固定深色不被系统来源覆盖。没有修改 Windows 全局配色。
- 简约灰、暖砂、雾蓝各自的浅色与深色，共 6 项：900×620 内容窗口，界面 17px / 内容 20px / 代码 18px，输入工具栏保持单行且无相互覆盖，页面无横向溢出，侧栏底部可滚动访问。逐项输出会话与设置截图。
- 窄窗口审查仍是左侧 Diff、右侧文件树。
- 真实 PowerShell PTY 在跨主题、设置页、编辑视图、面板隐藏后，创建次数为 1、终止次数为 0、PID 不变；再次发送独立验收标记仍收到输出，最后正常退出测试进程。
- 重新加载独立测试页面后，暖砂、绿色强调色、跟随系统偏好恢复；未发送草稿不要求跨应用重启持久化。

发现并修复：输入框和终端的 ResizeObserver 回调同步写尺寸会触发循环通知，改为下一帧合并调整并在卸载时取消；最小窗口叠加最大字号时，侧栏底部入口可能被裁切，允许侧栏纵向滚动。修复后重跑，渲染错误列表为空。

截图复核发现隐藏 Electron 窗口可能未绘制恢复可见的编辑区；在可见的独立验收窗口中复验，编辑区和未保存内容显示正常。验收脚本使用 `showInactive()` 展示测试窗口，避免后台截图误判；未为此修改产品编辑器样式。渲染错误在重载前后分别检查，避免重载清空错误记录。

常规验证：83 个测试文件、488 项测试通过；类型检查、生产构建及渲染资源检查通过。结果与截图保存在 `.cache/theme-acceptance/results.json` 及同目录 PNG（不提交 Git）。

边界：覆盖本机显示缩放、1280×820 初始窗口与 900×620 极限布局；不声称覆盖所有 Windows DPI、多屏组合、所有字体和业务页面。面试及知识工坊仍按 P5/P6 迁移。


## P5 接入范围

`workspaceThemeCss()` 对 Agent、智慧面试与知识工坊生成相同语义配色。面试现有结构样式位于 `styles.css`，统一布局与交互覆盖位于 `styles/interview.css`。后续新增面试组件使用主题变量，正文遵循内容字体，调试原文继续使用代码字体。默认收起的参数栏可从右上角展开，小窗口为浮层。

运行 `npm run verify:interview-ui` 可重复隔离界面验收，范围及限制见设计规划 10.9。


## P6 知识工坊接入范围

知识工坊统一布局位于 `styles/knowledge.css`，沿用公共主题变量。长配置使用 `KnowledgeDialog`，限制视口高度、固定标题与底部操作；危险操作打开后明确聚焦取消。避免再引入原生确认框、固定紫色按钮或浅色专用预算卡片。

运行 `npm run verify:knowledge-ui` 重做隔离界面验收，截图与结果位于 `.cache/knowledge-acceptance`。验证范围为三个主页面的六套明暗配色、窄窗口、提示词编辑保留、资料选择取消/应用、预算与导入弹窗、删除确认及任务列表收起。后端使用虚构响应，不覆盖真实模型生成与发布。

### 字号与弹窗层级补充

侧栏分组标题、条目、计数统一以 `12px + ui-font-adjust` 为基准，靠字重区分层级，不能让按钮继承浏览器默认字号。弹窗标签、输入值和按钮使用相同 UI 字号；说明文字只降低一级，标题最多提高两级。参数按逻辑成组，页签和内容区避免层层套边框；长提示词使用有限高度的只读预览。

会话过程详情必须约束每层 grid/flex 子项的 min-width；网格列使用 minmax(0, 1fr)，摘要单行省略，完整命令在详情内换行。验收必须包含千字符命令及窄会话列，检查详情右边界，而不只检查短内容截图。

会话过程采用紧凑时间顺序：记录间距 6px，工具子项间距 2px，过程文字使用正文色，工具和思考摘要使用次要色。单次工具调用直接展开详情，多次连续调用才使用分组；摘要用动作说明代替重复的“已完成”，折叠箭头跟随摘要。保留失败提示、思考原文、检查器入口及手动展开状态。此处仅调整 Pi 原有事件的展示，不增加进度汇报提示词或模型调用。

会话左缘使用细刻度按用户轮次导航，悬浮或键盘聚焦显示提问/回答摘要，点击通过虚拟列表定位，不依赖未渲染的 DOM。项目文件顶栏入口再次点击返回会话。普通发送先展示待确认气泡，后端消息到达后去重替换；排队、命令执行沿用原语义。请求完成不可清空用户随后输入的草稿，失败须撤销待确认气泡并恢复输入。`node scripts/verify-chat-ui.mjs` 验证切换、20 轮跳转、延迟 RPC 前即时显示、确认去重及失败恢复。

### 内置浏览器

Agent 顶栏的地球入口打开右侧浏览器，沿用宽面板的拖拽尺寸。支持地址栏、前进/后退、刷新/停止、本地 HTML 选择和网页的系统浏览器入口。会话 Markdown 中 HTTP(S) 和 HTML 链接可打开该面板；不新增 Agent 工具。关闭面板保留页面，退出客户端销毁页面；暂不提供多标签、下载管理或持久登录。

网页使用独立 session 的 WebContentsView，无应用 preload、Node 权限；本地 HTML 通过随机标识的 pi-preview 协议读取其目录内允许的网页资源，校验 realpath 阻止越界。应用弹窗或设置展示期间隐藏网页原生视图，避免遮挡。网页正文保持网站自身样式，浏览器工具栏使用应用主题。

运行 `node scripts/verify-browser-ui.mjs` 验证 HTML 链接、JS/CSS 与游戏交互、关闭重开状态、弹窗遮挡、刷新与历史、localhost、权限隔离、目录边界和销毁；隔离样例与截图位于 `.cache/browser-acceptance`，不覆盖第三方登录兼容性。
