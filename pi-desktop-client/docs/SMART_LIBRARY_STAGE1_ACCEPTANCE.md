# 智慧图书阶段 1：原文定位与可恢复索引

状态：2026-09-28 用户确认索引构建完成，并明确同意进入阶段 2。用户指出章节没有完全按原书划分，接受暂缓处理。以下为阶段 1 原始测试说明；最新检索能力见阶段 2 验收文档。

## 如何测试

1. 客户端开发终端输入 `r` 回车，更新主进程、preload 和索引 Worker。
2. 点击“图书索引”“图书问答”或“召回评测”会自动检查并启动默认本地模型服务。面板显示检查中、自动启动中、已就绪或失败原因，失败后可“重试启动”；健康检查通过前不能开始索引、提问或评测，仍可查看原文和历史记录。无需另开模型终端，已有服务会复用，多个面板不会重复启动。关闭面板不停止服务，退出客户端会停止自己启动的服务。仅启动默认端口 18081，自定义接口提示自行启动。手动控制和 `npm.cmd run library:models` 仍可使用。仅打开客户端或进入书架不加载模型。
3. 在智慧图书打开一本 TXT 或 EPUB，点击右上方“图书索引”。建议先用短书，随后使用《凡人修仙传》。
4. 点击“准备索引”：后台读取保留的原始文件，建立定位与关键词数据，显示原文章节数、片段数、预计请求批次。此操作不调用向量模型；准备期间可以关闭弹窗、继续阅读。
5. 核对“原文定位”中的章节、片段和字符范围，然后点击“开始索引”。可以切换模块、关闭弹窗；回来后仍能看到进度。
6. 中途点击“暂停索引”，确认已保存批次不丢失。退出并重新启动客户端，点击“继续索引”，应从保存进度继续。暂停会放弃当前未保存批次，它可能重新计算。
7. 停止本地模型服务，检查错误提示；恢复模型服务后点击继续。停止客户端时会中断后台任务，下次变成暂停状态，不会自动开始模型处理。
8. 已完成后点击“重建索引”：应用内确认后只准备新版本，再手动点击开始。期间旧的已生效版本保留；失败不会使它失效。
9. 检查原有图书目录和阅读位置、浅深色与窄窗口；反馈索引速度、原文定位和操作体验。

重排模型的选择不影响本阶段；这里只调用已保存的向量模型。更换向量模型、接口或同名模型权重后应重建，不能混用旧向量。分数与问答质量在后续阶段测试。

## 数据与恢复

- 数据在应用用户数据的独立 `smart-library` 根目录。原 `book.json`、阅读分页文件和原书保留，首次准备前另存 `book.before-index.json`。规范化原文由 original 文件建立，不把阅读分页当成章节。
- `indexes.sqlite`（WAL）：原文章节、段落、定位片段、FTS5、任务检查点和有效版本指针。
- `vectors/<版本 UUID>/`：对应 LanceDB 向量数据。完整校验后才切换有效版本，读端后续只使用有效版本。
- 一个片段最多 800 UTF-16 字符，约 80 字符重叠；不截断代理对。范围 `[start,end)` 可以从规范化章节精确还原。前后片段 ID 不跨章。
- 模型推理每次仍为 2 条；向量结果在内存积累至 64 条后再写入 LanceDB、提交 SQLite 检查点。正常暂停或模型失败时保存已算好的不足 64 条结果；突然退出时最多重算尚未提交的 64 条。恢复时只删除数据库中超出检查点的尾部，已完成部分复用。
- 建库完整性验证通过后，先合并小文件、校验全部向量和片段元数据，再通过 LanceDB 维护 API 清理历史，只保留当前有效向量数据和一份当前清单；不保留 24 小时历史。新索引发布前没有读取连接，允许清理近期孤立文件。整理失败会保留可用索引并提示；数据校验失败时不切换新索引。
- 已完成的旧索引可在退出客户端后，在开发目录用 Electron 的 Node 模式运行 `scripts/optimize-library-index.cjs --apply` 整理；默认不带 `--apply` 只统计。脚本检查客户端/建库/评测已停止，校验全部向量及抽样排名；SQLite 清理遵循相同保留规则，保留原书、会话与题库，报告写入 `.cache/library-storage-maintenance/`。
- 一次运行一个图书索引任务。正常只保留一套有效索引；重建期间临时保留有效旧版本和最新待完成版本，重新准备时清理此前废弃的待完成版本。新版本完整校验成功、旧检索及引用读取连接释放后，在切换有效指针的同一事务里删除旧片段、FTS、任务及不再使用的原文/段落数据；随后删除旧向量目录、压缩 SQLite 回收空间。失败时保留可续建的新版本和有效旧版本，不会丢失已生效索引。清理只在建库/显式维护时执行，不增加客户端启动工作。
- EPUB 的原文章节以阅读顺序中的 XHTML 文件为单位，TXT 使用章节标题识别；无标题 TXT 视为一章。仍沿用当前文本预览的提取范围，不新增 OCR/图片正文解析。

## 客户端管理模型服务（2026-09-28）

- 新增启动/停止、加载耗时、GPU、失败提示与可展开启动日志。只在用户点击时启动，弹窗关闭后继续运行，客户端退出或开发重启时停止自己启动的服务。
- 只管理默认本机 18081 端口，不覆写自定义接口。已有外部服务可复用但不接管；未知端口占用明确报错。索引或模型测试运行时拒绝停止，需先暂停。

- 已实测真实 GPU 后台启动、停止、启动途中取消、退出回收、外部服务识别、端口冲突和任务保护；界面使用模拟状态验证按钮及浅深色/窄窗口。Windows 下原生推理依赖先初始化，再启动退出监视线程，解决实测发现的启动卡住。
