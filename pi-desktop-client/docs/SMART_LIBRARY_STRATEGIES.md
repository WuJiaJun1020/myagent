# 智慧图书回答策略

## 方案 2 · 多路证据覆盖（2026-10-01）

策略列表自动提供独立的“方案 2 · 多路证据覆盖”，普通 RAG 的配置与旧索引保持原样。新方案仍须在策略管理的“索引”页面为图书建库，不会在客户端启动时加载模型或建立索引。

默认沿用 800 字片段、80 字重叠及当前本地模型。每条查询分别取关键词 40、向量 40 个候选；总候选池 48（可改至 64），返回 16 个片段，回答最多 12 个合并引用、16,000 UTF-16 字符，前后扩展各 240，重排批量 4。

执行流程：

1. 使用“问题处理模型”与思考程度做一次检索规划，未指定模型时沿用回答模型。规划提示词与原问题、必要历史完整记录在调试中。最多 4 个子问题，保留原问题；简单问题可返回空数组。有指代时要求给出至少一个独立问题。规划启用时不会重复执行旧的单问题改写。
2. 原问题和各子问题分别混合检索。先预留各路关键词/向量独有候选，再轮流填充总候选池；候选 ID 去重，高度重叠过滤遵循配置。GPU 服务接受单请求，查询路线顺序执行，避免并发 429。
3. 每个候选按入选时的查询路线重排一次。不同路线的分数不直接比较，按各自排名轮流取证据。一个片段可以记录多个来源，但当前只归属于一个重排路线，控制总重排开销。
4. 同章节扩展原文存在重叠或首尾相接时合并引用，验证重叠文本一致，保持精确原文坐标和全部源片段 ID。超出字符预算的片段跳过，继续尝试较短片段；不跨章节合并、不越过会话检索页码范围。关闭重叠过滤后不合并原文。
5. 问答与评测共用上述管线。规划、向量或重排异常可在问答中显式降级；评测将该题标记失败，避免把回退策略的结果计作完整新方案。

图书问答“调试信息”显示规划模型完整请求与返回、查询路线、候选来源/归属/排名/分数、返回筛选原因、上下文合并及预算取舍。评测题目详情提供“多路检索与证据筛选”和“实际回答上下文”。关键词、向量阶段表示各查询结果的并集，阶段标题显示“各路≤N”，不能与旧方案的同名阶段当作相同候选数量比较。

评测新增“返回字符”：将每题最终返回片段（`row.hits`）的正文 UTF-16 长度直接累加，重叠文字重复计入，不含扩展上下文、提示词和历史。单题列表与详情显示总数，总计/分难度和多方案对比显示成功题平均值；成功但无返回片段为 0，失败或无法读取的历史报告为“—”。旧报告用已保存片段补算，历史比较数值只缓存于内存，不重复保存正文或反复读取报告；JSON 导出含逐题字符数和分组统计。该指标衡量返回文本量，不冒充实际 token 用量。

做参数对照时复制方案 2 并关闭检索规划，保留同样的候选数、上下文预算与模型。另保留普通 RAG 作原始基线；比较分难度召回、全证据找齐题数与耗时，不把增加原文预算的收益全部归因于拆分。规划会增加一次模型请求，扩大候选池也会增加重排耗时，真实收益由常驻题集验收。

关闭规划会回到原有单查询管线（包括原来的上下文组装），因此若要进一步隔离合并逻辑的贡献，应另做上下文组装消融。该版本没有启用 GraphRAG、自动补检索轮次或修改切片。

## 策略管理与独立索引（2026-10-01）

智慧图书的书架与阅读器工具栏统一使用 **策略管理** 入口。左侧管理方案，右侧提供“配置”“说明”“本地模型”“索引”四个页签；不再单独提供本地检索模型和图书索引按钮。

“说明”页独立展示方案简介、问答流程图与建库流程图，并按当前配置说明切片、问题处理/多路规划、关键词/向量召回、RRF、重排、上下文组装、回答记忆及评测差异。说明实时反映草稿参数，明确未保存状态；简介沿用原有保存字段，可在此页编辑与保存。切换方案时保留说明页，方便对照；查看说明不会加载模型或索引。

“本地模型”页配置当前方案的向量与重排接口、模型，保留服务启动/停止、向量测试、8 组重排案例与多模型排序对比。测试使用当前填写值；修改与策略参数共用草稿，点击“保存方案”后生效，不覆盖其他方案。切换页签保留测试结果，离开模型页停止状态轮询；仅打开策略配置不会启动模型。

使用流程：

1. 复制“普通 RAG”或新建方案，在“配置”和“本地模型”中修改参数与模型，保存。
2. 进入该方案的“索引”，选择图书，准备原文并开始建库。复制方案只复制配置，不复制索引。
3. 图书问答输入框选择方案，会话记忆选择。已有回答、草稿和引用不会被删除。
4. 召回评测选择方案，或展开“多方案对比”勾选多套方案顺序评测。对比视图集中显示报告，点击“查看”返回该报告的题目与原文引用。

### 可配置内容

| 配置组 | 参数 |
| --- | --- |
| 切片与向量索引 | 按标点/段落边界或固定字符切片、长度、重叠 |
| 本地模型 | 当前方案的向量/重排接口与模型、服务管理、向量与重排测试 |
| 问题处理 | 关闭改写、仅有历史时改写、每次改写；独立模型、思考程度与提示词 |
| 召回与重排 | 关键词/向量/混合、两路候选量、融合量、RRF 常数、重排开关/批量、返回片段数量 |
| 上下文组装 | 证据数量、前后原文扩展、字符预算、候选重叠过滤 |
| 回答生成 | 默认模型与思考程度、最近历史轮数、附加回答提示词 |

回答模型在问答中用作输入框默认值，用户当前可见的模型/思考选择最终生效，并写入本轮快照；评测使用方案模型，未指定则冻结启动时客户端默认模型。问题处理模型未指定时沿用本轮回答模型。改写输出要求为 `{"query":"检索问题"}`，每轮完整请求、网关上下文与用量沿用调试入口。最终回答保留依据证据与引用校验的基础规则。

问答和召回评测共同执行 `qa/rag-pipeline.ts`：改写→检索/重排→原文上下文组装。评测题独立、无历史、全书范围，所以“仅有历史时”不会触发改写；要对比模型处理效果请选择“每次执行”。评测不生成最终答案，不是答案正确率测试。改写/检索/重排发生降级的题明确标失败，不混入正常召回率分母。

### 存储与兼容

以下路径相对应用的智慧图书数据目录：

```text
strategy-profiles.json               # 方案设置，保存时递增配置版本
indexes.sqlite + vectors/           # standard-rag 默认方案，复用既有索引
strategy-indexes/<方案ID>/
  indexes.sqlite + vectors/         # 新方案自己的索引、片段、FTS 与规范化原文
<图书ID>/original.txt|epub + *.txt    # 原始图书和阅读页仍共享
evaluation/<图书ID>/
  latest.json | <方案ID>.json        # 各方案最近报告
  runs/<运行ID>.json + runs.json     # 评测历史与对比摘要
```

原书、阅读页、GPU 环境和模型权重共享；索引数据库内的规范化章节、切片、关键词与向量分别保存。新方案的索引不会与其他方案共享或互相清理。每套方案/图书保留一份当前有效索引；建库时允许一份待完成索引，成功切换后清理旧版本，LanceDB 最终只留一份清单。评测报告是可回看的比较结果，不是向量历史副本。

默认“普通 RAG”兼容原有切片规则，直接沿用已有有效索引。修改名称、检索/重排参数、上下文或提示词不要求重建；修改切片或向量接口/模型后，已有索引标记不匹配，问答和评测会要求重建。修改用户数据后不自动重建。

报告冻结方案名称、配置版本、完整参数、索引版本、题集哈希和模型选择；保留实际改写问题、请求诊断、分阶段耗时及证据坐标。后续改名或修改配置不改变旧报告。同一份规范化原文即使重新切片，历史评测的原文坐标仍可定位；原文来源改变时拒绝错误跳转。

模型、数据库与策略对话框按需启动/加载。方案排队评测一次只运行一套，关闭面板后继续；停止会取消当前模型调用并跳过剩余方案。重新打开面板能看到当前队列。客户端退出会停止任务并保留已保存结果。运行中拒绝索引重建；编辑配置只影响后续任务，当前任务仍使用启动快照。

## 初版策略入口记录（2026-09-29）

普通 RAG 已接入策略注册结构。图书输入框左侧提供回答策略入口，与右侧模型/思考深度独立；上下文与缓存用量入口放在上一行。当前只提供普通 RAG，GraphRAG 尚未实现，不显示可用选项。

- 会话的 `strategyId` 持久化到 SQLite，旧会话与新会话默认 `standard-rag`。
- 策略变更只更新会话设置，不删除或隔离历史，不修改以往回答。模型、阅读范围仍为独立设置。
- 每轮保存实际策略的 ID、名称、版本快照；调试面板及导出的 JSON 可查看。旧回答明确标为历史记录，版本未记录，不伪造版本。
- 生成中禁止改策略；保存策略过程中禁止发送。后端按已保存会话确定策略，客户端提交过期选择则报错；未知策略不静默回退。
- 现有追问改写、最近四轮历史、混合检索、重排、六条证据、范围约束、提示词与引用校验保持不变。本次不重建任何索引。

## 后续添加 GraphRAG 或其他策略

1. 新建策略实现并注册，分配稳定 ID 与实现版本；版本在行为/提示词策略变化时更新。
2. 重型依赖和模型只在执行/构建时按需加载，不能因列出策略而拖慢客户端启动或其他模块。
3. GraphRAG 需要独立图索引状态、版本和就绪检查。实现时再增加按图书返回的可用性/准备入口，不复用普通索引状态冒充图索引就绪。
4. 实体、关系、摘要均保留原文来源；检索范围必须约束图证据。继续输出统一原文引用，保障定位与历史证据回看。
5. 历史无需按策略分隔，但需要按该策略的数据版本判断是否可用。不同策略严格比较效果时应新建会话。
6. 新策略先独立测试、由用户验收后进入下一阶段。不要为了演示选择框，增加没有实现的可选策略或静默降级。

## 验收

- 打开旧会话、创建新会话，均显示普通 RAG；关闭/重开后设置保留。
- 打开策略菜单可看到说明；选择后自动收起，历史及输入草稿保留。
- 发送一个问题，回答及调试信息显示实际策略和版本；生成期间入口禁用。
- 验证追问、停止、引用跳转、自定义检索范围、重命名/删除会话与之前一致。
- 检查浅深色、窄窗口、大字号和分栏拖动下，策略/模型工具栏不溢出。


本次验证结果：13 项问答流程测试、原生 SQLite 策略保存/重启恢复/未知策略拒绝、隔离 Electron 界面验收、类型检查和生产构建均通过。已检查浅深色及窄窗口大字号截图。独立冷缓存模块加载验证通过，运行数据目录未进入 Vite 监听。测试使用自编图书与模拟模型，不代表 GraphRAG 已实现或长篇检索质量有提升。
