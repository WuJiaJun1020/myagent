# 智慧图书：单本图书 RAG 开发与验收计划

> 创建：2026-09-28
> 当前状态：阶段 2 已获用户明确授权继续；章节识别差异和检索遗漏继续保留为已知事项。
> 当前阶段：阶段 3 基础问答与引用闭环，开发自测完成，待用户亲测。尚未进入阶段 4。
> 执行原则：每次只推进一个阶段；开发者完成自测后交付用户亲测，用户明确满意后才进入下一阶段。

## 1. 目标与范围

在现有 TXT、EPUB 导入和阅读功能上，实现针对**用户选定的单本图书**提问。回答应能找到原文依据，支持点击引用返回阅读位置，重点逐步解决细节、跨章节、时间顺序、错误前提和统计类问题。

采用：**混合检索 → 重排 → 原文上下文扩展 → 有限多轮查证 → 带引用的回答**。

不承诺所有问题都能回答。找不到充分证据时，应指出缺口；“没有检索到”不等于“全书不存在”。模型自身的记忆不能替代用户导入版本的原文。

本轮不做多书联合问答、联网补充书籍事实、OCR、语音和模块拆分。完整知识图谱不作为前置条件；是否增加摘要、事件表或关系索引，由后续评测结果和用户反馈决定。

## 2. 阶段推进规则

1. 启动阶段前阅读本文、上一阶段验收记录及相关代码，确认当前范围和未解决问题。
2. 开发、自测、修复、用户亲测均属于当前阶段。自动化检查通过只表示可以交付测试，不表示用户已经验收。
3. 每次交付说明：改了什么、如何启动或刷新、用户测试步骤、已知限制和测试结果。
4. 用户提出建议或发现问题时，先记录，再修复当前阶段的问题；新增需求先说明影响，按用户意见纳入当前阶段或列入后续事项。
5. **只有用户明确认可当前阶段并同意继续，才进入下一阶段。**没有回复、只问问题或仅有开发者自测结果，均不算验收通过。
6. 每次阶段交付和用户反馈后更新本文。重要设计变更也写入本文，不仅留在聊天记录中。
7. 不擅自提交、推送或发布版本；不修改 pi-agent 核心，不混入其他模块改造。

## 3. 当前代码基础

现有能力：导入 TXT/EPUB、保存原始文件和章节文本、目录预览、阅读位置记录。图书以文件哈希识别，存放在应用用户数据下的独立 smart-library 目录。

主要入口：

- `src/main/smart-library/library-module.ts`：导入、列表、读取及阅读位置 IPC。
- `src/main/smart-library/book-parser.ts`、`import-worker.ts`：格式解析和后台导入。
- `src/renderer/modules/smart-library/`：图书界面及状态。
- `src/shared/contracts/smart-library.ts`：前后端协议。

规划起点尚无 RAG 索引和问答；现已完成索引、阶段 2 检索及阶段 3 基础问答实现。解析器会将长文本拆为不超过约 14,000 字符的阅读片段，必须区分**原始章节、阅读片段、检索片段**，不能把现有显示分页直接当作检索分块。

## 4. 技术选择与模块边界

| 能力 | 初步选择 | 落地约束 |
|---|---|---|
| 原文 | 保留原始文件和规范化章节文本 | 规范化文本版本不可在原索引下悄悄改变 |
| 元数据、任务、会话 | SQLite | 图书专用数据库，不复用面试业务表 |
| 向量检索 | 已有 LanceDB 依赖 | 图书独立目录；所有查询限制 bookId、有效索引版本及阅读范围 |
| 关键词检索 | SQLite FTS5，配合中文分词或字符索引 | 阶段 0 验证运行时支持；两字人名不得只依赖 trigram |
| Embedding | 官方 Qwen3-Embedding-0.6B BF16；统一 CUDA 服务 | 用户明确不使用云服务；模型、维度和预处理版本共同决定索引兼容性 |
| Reranker | Qwen3-Reranker-0.6B BF16、BGE Base / v2 M3 FP32 可选；同一 CUDA 服务 | 阶段 0 比较后选定；需要真实评分接口，不可用聊天生成假装重排，不可静默回退云端 |
| 回答模型 | 复用客户端的模型配置和凭据管理能力 | 图书专用会话，不污染 Agent 工作区的对话或工具权限 |
| 编排与后台任务 | TypeScript 服务 + Worker | 避免解析、扫描和索引阻塞 Electron 主线程 |

候选模型不等于最终定型；用实际中文图书题集比较质量、耗时和费用后选默认配置。第一版不向安装包加入模型权重，也不新增必须部署的数据库或 Python 服务。

用户于 2026-09-28 明确要求向量化和重排使用本地模型。因此这两种能力只允许本机回环地址，禁止自动回退云端，HTTP 重定向也不接受。模型下载属于获取权重，不会上传图书，但首次下载体积和部署方式仍需说明。全书向量化前显示预估处理量。阶段 3 用户另行确认：回答复用客户端已配置模型，在图书面板中选择；同意向所选模型发送问题、相关对话和少量检索证据，不发送整本书。该授权不改变检索模型必须本地运行的要求。

建议结构，按阶段按需建立，避免先搭空框架：

```text
src/main/smart-library/
  library-module.ts          # 模块入口和 IPC
  library-database.ts        # 图书、任务、索引及问答元数据
  book-parser.ts             # 格式解析及章节边界
  indexing/                  # 切块、向量化、索引任务
  retrieval/                 # 关键词、向量、融合、重排
  qa/                        # 查证流程、回答、引用校验
  providers/                 # 模型能力适配
src/renderer/modules/smart-library/
  阅读器、问答面板、索引状态和引用定位组件
src/shared/contracts/smart-library.ts
```

## 5. 数据与检索约定

### 原文和引用

- 片段记录 bookId、sourceVersion、chapterId、paragraphId、起止偏移、前后片段 ID、文本哈希和切块版本。
- 偏移统一以规范化章节文本的 JavaScript UTF-16 字符串索引计数，采用 `[start, end)`；边界不得截断代理对。引用内容必须能由原文按该范围精确还原。
- 旧图书通过保留的 original 文件补建结构；迁移前备份元数据，保留阅读进度映射，失败可回退。
- 检索子块初始约 500～1,000 汉字，优先按段落/句子分割并少量重叠；同时满足模型 token 上限。这是评测起点，不是固定最终参数。
- 命中后可扩展相邻段落或父章节，但必须受阅读范围和上下文预算约束。
- 引用由程序从有效证据 ID 解析，模型不能自行编造章节号、偏移或原文引语。有效引用位置并不自动代表论断得到支持，还需核验语义。

### 索引生命周期

- 新索引先在独立版本中构建，完整校验后原子切换；不能暴露半成品，也不能在失败时破坏旧索引。
- 按批保存进度，支持取消、失败重试和客户端重启后继续；复用已完成且版本一致的向量，避免重复计费。
- Embedding 模型、维度、规范化或切块规则改变时，建立新索引版本，禁止混用。
- SQLite 和 LanceDB 的跨存储更新通过任务状态、版本标记和恢复检查协调，不能假定存在跨库事务。

### 查询和回答

- 关键词与向量并行召回，进行排名融合、去重、重排，再补充上下文；候选数量和预算根据评测调优。
- 两字人名、别名、罕见词和精确短语必须有可验证的关键词路径。
- 所有检索、摘要、事件记录和缓存都受 bookId、索引版本、阅读截止位置约束；过滤必须尽量前置，不能只在最终答案中隐藏后文。
- 会话历史用于理解指代，不作为原文证据；从全书模式切换到较早章节时，也不能把历史中的后文内容重新传入生成上下文。
- 书籍内容一律视为资料，不能执行其中的指令。答案区分原文明示、根据证据推断及证据不足。
- 日志记录耗时、候选 ID、各阶段状态和可用的实际 token 用量；没有用量时标为未知，不写作 0。常规日志不保存密钥或整本正文。

## 6. 分阶段交付与用户测试

### 阶段 0：测试基线与模型接入验证

**交付**

- 确认首本测试书及版本，可优先使用用户已有的《凡人修仙传》，另准备小型 TXT/EPUB 测试样本。
- 初始整理 15～20 道可人工核对的问题，后续逐步扩展到 50～100 道；不要求用户开工前标注全书。
- 题目记录问题类型、阅读范围、预期要点、原文位置和是否可回答。保留部分题目作为未参与调参的验收题。
- 验证候选模型接口、SQLite FTS5、中文短词检索和 LanceDB 过滤能力，给出实际接入方式及小样本测量结果。
- 提供最小的模型配置与连通性验证入口；费用较大的全书处理不在本阶段启动。

**用户亲测**

1. 确认测试书、题目难度、模型来源和数据发送范围符合预期。
2. 测试连接成功、配置错误和服务不可用时的提示。
3. 确认阶段 1 使用的模型、配置和索引处理方案。

**验收条件**：测试题有可靠依据，模型接口可用或替代方案明确；用户认可后再建完整索引。

### 阶段 1：原文定位与可恢复索引

**交付**

- 区分真实章节与显示分页，建立稳定的段落和引用位置。
- 实现关键词索引、向量索引，以及开始、进度、取消、继续、重建操作。
- 兼容既有图书数据，重建期间仍可阅读，旧索引可用时继续保留。

**用户亲测**

1. 分别导入 TXT、EPUB，检查目录、章节正文和原有阅读位置。
2. 为短书及长篇图书建立索引，期间继续阅读和切换模块。
3. 中途取消、重启客户端并继续，检查进度和完成状态。
4. 模拟网络失败后重试，确认错误可理解、原书没有损坏。

**验收条件**：全文无静默遗漏、引用片段可还原、界面不卡死、失败可恢复，用户认可索引体验。

### 阶段 2：混合检索与证据预览

**交付**

- 接入关键词、语义召回、融合、去重和重排。
- 提供可亲测的“查找原文”入口，展示命中片段、章节及上下文，点击跳转高亮。
- 支持全书及截至当前阅读页末尾的检索范围（实现比章节末尾更严格）；重排不可用时明确提示降级状态。
- 输出基线题目的证据召回结果，比较关键词、向量和混合检索的差异。

**用户亲测**

1. 输入两字人名、法宝名、原文短句及同义改写，查看结果。
2. 测试跨章节问题能否找到多处必需证据。
3. 点击引用，确认位置和高亮正确；切换书籍及阅读范围，确认不串书、不泄露范围外正文。

**验收条件**：结果可定位、基础问题关键证据能召回；对遗漏有记录和解释，用户认可后再接回答生成。

### 阶段 3：基础问答与引用闭环

**交付**

- 阅读器右侧问答面板、流式回答、停止生成、每本书独立的会话持久化。
- 基于检索证据生成回答，引用可展开并跳转；无依据时说明不足。
- 处理追问中的指代、请求失败和会话恢复；切书后迟到的响应不能写入另一书籍的会话。
- 测试书籍内类似提示词的文本，确认不会被当作操作指令。

**用户亲测**

1. 提问细节、连续追问，检查答案及每处引用。
2. 提出书中没有答案或前提错误的问题，检查是否编造。
3. 生成途中停止、切书，重启客户端后检查记录。
4. 在浅深色、窄窗口和大字号下检查阅读与问答布局。

**验收条件**：基本问答闭环可用，引用真实且支持相应论断；没有跨书污染，用户认可交互和回答质量。

### 阶段 4：刁钻问题与多轮查证

**交付**

- 对复杂问题拆分检索任务，补充上下文和缺失证据；每轮明确检索目标。
- 增加有原文依据的别名扩展、跨章节对照和时间顺序验证。
- 设置轮数、耗时、上下文和调用预算；达到上限时返回已查明部分及证据缺口，不无限重试。
- 展示简洁的查证进度与实际参考证据，不展示或伪造模型内部思考过程。

**用户亲测**

1. 测试跨章节原因、人物不同称呼、相似事件混淆等问题。
2. 测试“首次/最后一次”，检查是否只是拿第一个搜索结果当答案；覆盖不足时应保留结论。
3. 故意提出错误前提，检查助手能否依据原文纠正。
4. 检查耗时、停止响应和预算耗尽提示是否可接受。

**验收条件**：相较阶段 3，复杂题有可量化改善且基础题不明显退化；失败案例透明，用户认可质量与速度的取舍。

### 阶段 5：全局问题与覆盖型查询

**交付**

- 为主题、人物变化等问题按需建设章节/分层摘要索引，摘要保留原文来源，事实回答仍回原文核实。
- 为“列出所有、总共几次、从未发生”等问题实现有覆盖记录的扫描、事件抽取和去重，不能用 top-k 命中数量当统计结果。
- 报告扫描范围、未处理部分和可能歧义；词语出现次数与事件发生次数明确区分。
- 阶段启动时根据失败题集决定是否需要事件表或人物关系索引，必要时更新本计划；不默认建设完整 GraphRAG。

**用户亲测**

1. 用可人工核对的限定章节范围测试统计与列表，再扩展到全书。
2. 检查回忆、转述、重复提及是否被重复计为事件。
3. 测试成长轨迹、主题对比和否定型问题，检查原文依据及覆盖说明。
4. 核对额外索引耗时、空间和模型费用是否值得。

**验收条件**：覆盖范围可查，统计口径明确，无法证明完整时不冒充完整；用户决定是否接受增强能力和成本。

### 阶段 6：稳定性、性能和打包验收

**交付**

- 完整回归固定题集及保留验收题，整理最终质量、延迟、索引体积和调用量报告。
- 验证长篇索引、应用异常退出、恢复、模型变更、旧数据升级和残留索引处理。
- 在 Windows 安装包中验证 SQLite、LanceDB、Worker 及数据路径；不新增不必要的运行时或模型权重。
- 更新使用说明、已知限制和故障恢复指引。

**用户亲测**

1. 安装版完整走通导入、索引、问答、引用和恢复。
2. 测试中文路径、长书、网络异常、关闭重开及旧图书数据。
3. 提供新的刁钻题，检查实际使用效果，确认安装体积和运行资源可接受。

**验收条件**：影响阅读、数据完整性和问答可信度的问题已解决或经用户接受；用户明确确认本轮交付完成。发布另行决定。

## 7. 评测和交付规范

每道题至少记录：题目 ID、图书版本、阅读范围、类型、标准要点、必需证据集合、实际检索证据、回答、引用、耗时及用量（可取得时）。

分别评估：

- **证据召回**：所需片段是否被召回；多跳题检查必需证据是否找齐。
- **回答正确性**：是否忠于当前版本的原文，是否遗漏关键条件。
- **引用质量**：位置是否正确，原文是否支持关联论断。
- **证据不足处理**：是否合理保留结论；也避免有证据却一概拒答。
- **覆盖和隔离**：统计范围是否完整，是否串书或泄露阅读范围外信息。
- **体验与成本**：索引耗时/体积、首字及总耗时、请求量、实际或估算费用。

模型打分只辅助分析，不能取代人工核对；模型生成的测试答案未经原文核对不得成为标准答案。数值目标在阶段 0 取得基线后与用户确定，不把未经测量的准确率写成承诺。

各阶段至少运行相关自动化检查和实际界面检查。费用较高的全书模型回归先说明规模，不以无限调用换取偶然通过。交付时保留失败题，不删除难题美化成绩。
