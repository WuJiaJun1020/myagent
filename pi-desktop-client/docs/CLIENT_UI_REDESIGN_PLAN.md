> 版本：1.3

## 1. 目标与边界

### 1.1 用户目标

客户端各部分保持统一、简洁、美观。Agent 工作区先成为可以实际使用和对照的样板，后续业务页面复用它的视觉规范、公共控件和主题机制。

参考 Codex 的内容层级、布局和外观设置方式，保留 Pi Desktop 自己的模块划分和功能。统一视觉不意味着强行把对话、题库、代码编辑和资料审核做成相同布局。

### 1.2 本计划的边界

- `pi-agent/` 核心源码不在改造范围内。
- 首批实现集中在 `pi-desktop-client/src/renderer`；必要时调整前端布局、主题和偏好状态。
- 保留模型调用、流式事件、消息队列、审批、会话存储、工具执行、文件操作和 Git 操作的既有语义。
- 不借界面优化改变面试提示词、导演逻辑、题库召回、知识生成和审核流程。
- 所有现有功能必须可达；折叠详细信息时保留展开入口，不通过隐藏错误、删除日志来获得简洁外观。
- 保留用户已有字体、字号、面板尺寸及会话草稿，不因为更换默认设计而重置个人设置。
- 本文中的尺寸、主题名称和交互细节为建议规格，须通过样板页面验证后固定；不代表已经实现。

## 3. Agent 工作区的目标样式

### 3.1 视觉原则

1. **内容优先**：正文、任务状态和当前操作比装饰标题、统计数字更醒目。
2. **中性底色**：以白、灰和柔和深灰构建表面层级；强调色只承担操作与选择提示。
3. **轻量边界**：优先使用间距、对齐和少量分隔线；普通内容区不添加重阴影。
4. **一致控件**：按钮、输入框、选择器、标签、列表项在各页面遵循同一套规格。
5. **渐进展开**：摘要默认可见，原始输入输出和细节可展开；错误与待审批状态始终可发现。
6. **稳定布局**：消息增长、切换主题、展开工具记录时，不无故改变阅读位置。

### 3.2 默认布局

```text
┌────────────────────── 应用标题栏 ───────────────────────┐
│ 模块与项目导航 │ 当前项目 / 会话          文件 审查 终端 │
│               ├────────────────────────────────────────┤
│ 常用工具      │                                        │
│               │              对话正文                  │
│ 最近会话      │                                        │
│               │ 工具执行摘要（可展开）                  │
│               │                                        │
│               ├────────────────────────────────────────┤
│               │ 输入区                                 │
│ 设置 / 状态   │ 附件   工作模式   模型 / 思考    发送     │
└───────────────┴────────────────────────────────────────┘

需要查看详情时：主内容 + 可调整宽度的右侧面板。
需要终端时：在工作区底部展开，关闭面板不等于结束终端进程。
```

- 默认阅读状态不常驻只有导航链接的右侧栏；工具入口在侧栏或顶部仍然可达。
- 用户主动打开的详情保持可见，尊重已有开关和尺寸偏好；不按每条消息自动重置。
- “项目文件”和“代码审查”继续有明确入口；多个入口指向同一个状态与视图，不生成重复编辑实例。
- 聊天正文与输入框保持对齐；可读宽度建议 720–880px，空间不足时自然收缩。
- 宽代码、表格和 Diff 可使用更宽的内容区域或自身横向滚动，不把正文撑出窗口。

### 3.3 基础规格草案

以下为 CSS 逻辑像素，必须结合 Windows 显示缩放验证，不以屏幕截图像素直接反推。

| 项目 | 建议规格 |
| --- | --- |
| 默认界面正文 | 14px；列表元信息、说明 12px，重要操作不使用极小字号 |
| 对话正文 | 新默认值建议 14px；保留用户已有内容字号 |
| 标题 | 页面 22–24px，区域 16px，列表标题 14px |
| 行距 | 普通 UI 1.4–1.5；长文 1.65–1.75；代码独立配置 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px |
| 常规控件高度 | 36px；紧凑工具栏 32px；图标按钮命中区域不小于 32px |
| 圆角 | 控件 8px；面板 12px；输入主区域 14–16px；状态标签可用胶囊形 |
| 图标 | 统一使用现有 Lucide，通常 16–18px、相近线宽 |
| 侧栏 | 默认约 236px，继续可拖拽；长名称省略并可查看完整文本 |
| 页头 | 一层主标题与操作区；避免装饰标题、面包屑和工具栏重复占高 |
| 边框与阴影 | 单层弱边框；阴影主要用于浮层、菜单和弹窗 |
| 动效 | 通常 120–180ms；尊重减少动态效果设置，流式内容不逐字位移动画 |

正常、悬停、按下、选中、焦点、禁用、加载、失败都需要定义。选中和焦点不能只靠文字颜色区分；危险操作保留明确文字与既有确认机制。

## 5. 主题与公共组件基础

### 5.1 主题设置模型

将三类设置分开：

| 设置 | 内容 |
| --- | --- |
| 明暗模式 | 跟随系统 / 浅色 / 深色 |
| 配色主题 | 简约灰、暖砂、雾蓝，每套都提供浅色与深色配置；名称暂定 |
| 阅读设置 | 界面字体、内容字体、代码字体及各自字号 |

阶段 P1 先建立“简约灰”的深浅配色和完整颜色接口；阶段 P4 再加入其他主题与强调色选择。旧的 `theme = light / dark / system` 表示模式，继续保留其含义；新增主题标识，不复用该字段保存主题名称。

建议首版预设方向：

| 主题 | 浅色方向 | 深色方向 | 强调色方向 |
| --- | --- | --- | --- |
| 简约灰 | 中性白与浅灰 | 柔和石墨灰 | 克制的蓝色 |
| 暖砂 | 暖白与浅米灰 | 暖深灰 | 低饱和陶土色 |
| 雾蓝 | 冷白与蓝灰 | 深蓝灰 | 柔和蓝色 |

精确色值在样板验收时确定。不要直接把暗色文字反转成白色，或将用户提供的任意强调色直接用于白字实心按钮；需同时定义该颜色上的可读文字。

高级自定义背景、前景与颜色输入可作为后续独立任务。主题导入导出、主题市场、透明材质和背景图片暂不进入本轮必做范围。

### 5.2 颜色按用途定义

建议由主题提供以下语义值，页面不自行决定同一类控件的颜色：

- 表面：应用、侧栏、内容、浮层、悬停、选中。
- 文字：主要、次要、辅助、禁用、强调色上的文字。
- 边界：普通、强调、键盘焦点。
- 操作：强调色、悬停、按下、弱背景。
- 状态：成功、警告、失败、进行中，同时配文字或图标。
- 专用内容：行内代码、代码块、Diff 增删、编辑器选区、终端 ANSI 调色板。

当前 `styles.css` 已有 `--bg-*`、`--text-*`、`--accent-*`。实施时先清点和复用，按实际需要补足；避免同时长期维护两套同义变量。

主题入口统一产生变量，CSS 控件消费变量；编辑器和终端通过适配器消费同一主题，不各自再维护独立的 light/dark 常量。切换主题不应重建会话、编辑器文档或终端进程。

### 5.3 公共组件范围

优先完善已有 Button、Tooltip、TooltipIconButton，再按真实复用需要提取：

| 组件类别 | 统一内容 |
| --- | --- |
| Button / IconButton | 主操作、次操作、轻操作、危险操作、尺寸、加载状态 |
| Input / Textarea / Select | 高度、边框、标签、说明、校验、禁用态 |
| Tabs / SegmentedControl | 页面导航和局部模式选择分别定义，避免混用 |
| PageHeader / Toolbar | 标题、说明与操作区对齐 |
| ListItem / StatusBadge | 密度、选中态、状态语义 |
| Disclosure / Panel | 摘要、展开按钮、原始内容区域、可访问名称 |
| Dialog / Drawer / Menu | 定位、层级、关闭、焦点和键盘行为 |
| EmptyState / ErrorState | 精简说明与当前可执行动作 |
| SettingsGroup / SettingsRow | 设置页与局部参数面板的共同样式 |

共享组件不导入业务 Store、RPC 或面试/知识工坊类型。沿用现有 React、CSS、Lucide 与组件工具，不为换外观引入另一套大型 UI 框架。仅在有复用收益时拆分组件，避免先造通用框架再寻找使用场景。

### 5.4 交互状态与浮层规范（后续页面沿用）

- 默认、悬浮、选中分别使用表面色、`--bg-hover`、`--bg-selected`；已选中项悬浮使用 `--bg-selected-hover`。不要把 `--bg-panel` 当作悬浮色，也不要只靠文字变色表示可点击。
- 浅色主题需在白色内容区和浅灰侧栏上都能看出悬浮区域；深色主题独立检查。最近会话、项目、模块导航、文件树、设置导航和图标按钮都纳入检查。
- 选中状态在鼠标移开后保留；键盘焦点使用清晰外轮廓，不与悬浮混用；禁用按钮不得出现可操作的悬浮反馈。按下不得改变控件尺寸或导致布局跳动。
- 提示统一使用 `HoverHint` / `HintButton`，不新增原生 `title` 提示框；iframe 的无障碍标题保留。选项沿用公共菜单或 `overlays.css` 的 select 样式。
- 浮层优先相对触发器居中，靠近视口边缘时避让；Escape 先关闭最上层选项。窄宽度下输入框工具栏保持单行，通过图标和省略文字压缩，完整信息由提示补充，不显示文本框拖拽角标。
- 验收至少覆盖浅色、深色的默认/悬浮/选中/选中悬浮/键盘焦点，以及禁用状态；保留代码审查左右布局。

## 8. 验收方式

### 8.1 视觉矩阵

| 维度 | 检查范围 |
| --- | --- |
| 配色 | P1–P3：默认主题浅/深；P4 后：三套主题各浅/深；系统模式另检查自动切换 |
| 窗口 | 1280×800、1440×900、1920×1080；记录实际内容视口；同时检查当前最小支持窗口 780×600 |
| 系统缩放 | Windows 100%、125%、150%，记录逻辑尺寸，避免把系统缩放误当成样式缺陷 |
| 字体 | 默认字体、内置中文字体；界面/内容/代码字号取默认值和允许范围两端 |
| 内容 | 长中文名称、长模型名、空列表、长代码、宽表格、工具失败、流式消息 |
| 面板 | 左栏开关、右栏开关、审查宽面板、终端展开；分隔条可达 |
| 键盘 | Tab 焦点、Enter、Escape、输入法、弹窗焦点恢复；隐藏面板不能接收焦点 |

文字对比度以普通正文至少 4.5:1 为内部验收目标，大字号与关键非文字控件至少 3:1。明确记录禁用态等例外，不能将重要说明设计成接近不可见。状态使用颜色加文字/图标，不单靠颜色区分。

最小窗口下允许导航或详情收束，但不允许主要按钮被遮挡、表单无法提交、内容只能依靠横向拖动才能读取。

### 8.2 行为回归

- 模块和会话切换：当前会话、草稿、滚动位置、已选项目保持正确。
- 流式输出：滚动跟随与手动回看不互相抢占。
- 输入：附件、队列、模型设置、停止和重试维持当前行为。
- 工具：审批和错误可见，原始内容可展开，详情不被新的展示文案改写。
- 编辑与终端：未保存状态、终端内容和进程在面板切换中不丢失。
- 设置：主题切换与重启恢复正确；已有用户偏好不被新默认值覆盖。
- 边界：`pi-agent/` 无改动，后端协议与业务算法无意外变化。

### 8.3 验证手段

- 每个阶段保存同一内容与视口的前后截图，检查长内容和异常状态，不只看空页面。
- 复用现有相关测试；有主题解析、设置恢复、布局状态等逻辑变化时补充有意义的行为测试。
- 不为每条 CSS 属性编写镜像测试。纯视觉调整主要靠组件示例和实际界面复核。
- 在相应阶段运行 `npm run typecheck`、相关测试；阶段集成时运行 `npm test`、`npm run build`、`npm run verify:renderer`。
- 渲染器资源检查仅证明构建资源有效，不替代人工视觉验收。
- 没有真实调用模型时明确标记“未做线上模型端到端验证”；界面改造不为凑测试而消耗真实面试或生成任务。

## 9. 主要风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 修改共享 CSS 提前影响其他模块 | 记录共享选择器与变量消费者，每阶段同时冒烟检查未迁移模块 |

| 一次性跨模块重做难以回退 | 依阶段交付，保留截图基线和清楚提交边界，不修改业务存储格式 |
