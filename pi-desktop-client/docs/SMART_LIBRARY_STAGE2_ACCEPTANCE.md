# 智慧图书阶段 2：混合检索与证据预览

状态：2026-09-28 用户明确要求进入下一阶段，已授权推进阶段 3。下文保留阶段 2 的测试记录；检索遗漏仍是已知限制，不能因进入下一阶段视为已修复。

## 用户测试

1. 开发终端输入 `r` 回车，更新主进程、preload 与 Worker。已经完成的索引直接复用，无需重建。
2. 在智慧图书打开已完成索引的书，点击右上角“查找原文”。语义检索、重排需先启动本地模型；弹窗空状态可展开“本地模型服务”启动，或使用原有“本地检索模型”入口。
3. 默认“截至当前阅读页”，包括本页的全部内容；需要搜索整本书时选择“全书”。当前按阅读页末尾截止，比“截至章节末尾”更严格，并非截止到屏幕滚动位置。
4. 试两字人名、法宝名、原文短句、同义改写和跨章问题。结果显示原文章节标题、候选片段、各路排名及可用的重排分数。
5. 展开“查看上下文”，核对高亮片段；点击“阅读原文”，应跳到实际阅读页并高亮。跨阅读页的片段先跳到首个相交页；完整片段与允许范围内的上下文仍可在证据预览中看到。
6. 对同一道题切换“仅关键词 / 仅语义 / 混合检索”，也可关闭重排，比较关键证据是否排在前列。模型可在原有设置中选择；更换重排模型不需要重建向量索引。
7. 在较早阅读页检查范围限制；切书、停止、关闭重开，确认没有迟到结果混入。停止模型服务后，关键词不启用重排仍可用；混合检索会明确提示语义或重排降级，仅语义则直接报告故障。

建议反馈：书名、问题、阅读范围、模型与检索方式、遗漏或应排在前面的原文。检索不到不等于书里不存在；高分也不等于问题能被回答。

## 实现边界

- 在已有索引 Worker 内查询，SQLite / LanceDB 不进入前端、不会阻塞 Electron 主线程。检索弹窗按需加载；未打开模型状态区时不轮询模型服务。
- 只读取 `active` 指向的完整索引，不读正在构建的新版本。FTS 中文 bigram 与精确短语召回最多 40 条，向量最多 40 条；RRF 融合、重叠去重，最多 16 个候选参加重排，展示前 8 条。
- Embedding 使用 `input_type=query`，核对索引中的模型、维度、权重 revision；不接受混用。只访问本机地址、禁止重定向，不自动使用云服务。
- 所有原文、向量及证据请求限制书籍和有效索引版本。阅读截止在召回前应用：跨截止点的向量不使用；关键词可使用截至截止点的原文前缀；重排和上下文均不含后文。
- 关键词服务失败不伪造结果；语义失败可降级关键词，重排失败保留召回顺序并说明原因。单次检索最多 90 秒；支持取消。同一索引 Worker 一次执行一个检索请求。
- 原有阅读文件保持不变，首次按需建立阅读页与规范化原文的精确映射，进程内最多缓存四本。映射失败时禁止有范围限制的检索、禁止错误跳转；全书证据仍可预览并显示定位错误。
- Qwen 与 BGE v2 M3 使用完整候选；BGE Base 使用 64 UTF-16 字符、16 字符重叠的覆盖窗口（代理对安全），每片段取最高窗口分数，问题最长 100 字符。服务端分词器继续强制校验 token 上限，超限明确降级，不截断正文。其他模型可能返回超限错误，需使用兼容服务。
- 标记“内部章节序号”避免误读成书中章号。用户接受暂缓的章节识别问题未修改；没有重写已有索引或图书。

## 自测

- 图书相关 19 项单测：解析、索引分块、模型配置、查询词、融合、重叠去重、重排窗口尾部与 Unicode。
- Electron Node + 实际 SQLite FTS5 / LanceDB 集成：两书隔离、旧有效索引、范围预过滤、跨边界片段、发往重排的正文无后文、证据精确还原与阅读页高亮、服务降级、权重版本不匹配、取消重试、过期引用和映射失败关闭路径。模型服务使用确定性模拟值，此组不评价模型质量。
- 实际 CUDA：RTX 4060，Qwen3-Embedding-0.6B + Qwen3-Reranker-0.6B，BF16。使用隔离的《山灯记》4 片段及《凡人修仙传》前六章 21 片段；没有重建或修改用户全书索引。
- 隔离 Electron 检查检索、上下文展开收起、跳转高亮、改条件清空旧结果、关闭、浅深色及窄窗口大字号。模拟向量及真实索引存储。
- 冷缓存模块加载回归：面试约 3.17 秒、知识工坊约 73 毫秒、智慧图书约 24 毫秒；监听 1,260 个文件。独立空页面导入计时，不是完整用户启动耗时。
- 类型检查和构建；构建仍有既有 Monaco 大 chunk 提示。

## 真实模型开发集基线

采用已标记 development 的 13 题；holdout 未用于本次检索测量或调参。对照关键词与语义均关闭重排，混合开启 Qwen 重排。统计标准是“候选正文包含人工证据锚点”，不是答案正确率。

| 样本 | 方式 | 前 3 条证据锚点 | 前 8 条证据锚点 | 本次单题耗时 |
|---|---|---|---|---|
| 山灯记，4 题 | 关键词 | 7/7 | 7/7 | 0–1 ms |
| 山灯记，4 题 | 语义 | 7/7 | 7/7 | 47–60 ms |
| 山灯记，4 题 | 混合 + 重排 | 7/7 | 7/7 | 213–259 ms |
| 凡人前六章，9 题 | 关键词 | 15/16 | 15/16 | 1–6 ms |
| 凡人前六章，9 题 | 语义 | 14/16 | 15/16 | 51–91 ms |
| 凡人前六章，9 题 | 混合 + 重排 | 14/16 | 15/16 | 323–1,299 ms |

F08 的两处证据中，片段 14 被召回，补充证据所在片段 16 未进入前三种方式的前八条；已核对该锚点确实存在于规范化原文和索引，属于排名/覆盖不足，不是丢失原文。这类问题后续可能需要扩大候选、邻近扩展或多轮查证，不能宣称已解决。此次不针对漏题硬编码规则。

小样本中混合并未优于关键词；四章短书的高召回也不能代表长篇全书效果。全书多情节干扰、别名和多证据覆盖仍需用户测试，尤其不能把该成绩当成最终 RAG 准确率。
