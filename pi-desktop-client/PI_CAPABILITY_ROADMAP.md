# Pi Desktop 能力对齐路线图

## 目标

将 `pi-desktop-client` 从“Pi RPC 的桌面展示层”逐步建设为可独立完成 Agent 工作流的桌面工作台。

设计原则：

- Renderer 只依赖桌面端统一契约，不依赖 Pi 内部类或 JSONL 文件格式。
- 优先接入 Pi 已有 RPC 能力；只有确有缺口时才扩展 Pi RPC。
- 凭据、绝对会话文件路径和项目外文件访问继续留在 Main Process。
- 每个阶段必须有独立的类型检查和定向测试，再进入下一阶段。
- 先补完整工作流，再扩展视觉效果；不为演示伪造 MCP、Memory 或 Agent 状态。

## 当前基线

已完成：提示词/流式输出、思考与 Tool 时间线、文件 Diff、终端输出、Provider 登录和模型选择、聊天/工作会话隔离、会话重命名与删除、工具批准、上下文使用量、手动压缩、文件树、MCP/Memory 运行时状态浏览。

当前缺口：队列控制、自动运行策略、多模态附件、直接终端、MCP/Skills/Memory 管理、完整 Extension UI、编辑器与 Git 工作流。

## 阶段 1：会话工作流补全

### 范围

- 会话信息页：消息数、上下文、输入/输出 Token、缓存、成本（以 Pi `get_session_stats` 为数据源）。
- 会话树：读取 Pi `get_tree`，在当前会话内跳转历史节点并继续工作。
- Fork：从历史用户消息创建独立会话。
- Clone：复制当前分支为新会话。
- 导出：导出 HTML 或 JSONL，路径由 Main Process 的保存对话框选择。
- 导入：选择 JSONL 后由 Pi 恢复为当前会话。

### 契约与安全

- 为 Pi Desktop 定义 `SessionTree`、`SessionStats`、`SessionExport` 等脱敏 DTO。
- Renderer 不接触绝对 session path；仅使用会话 ID、节点 ID 和用户选择的安全文件句柄。
- 导入路径由 Main Process 校验为本地 JSONL；导出路径由保存对话框产生。

### 验收标准

- 可从会话侧栏打开“会话详情”。
- 可查看树并跳转到指定节点，历史与当前分支同步刷新。
- Fork/Clone 后新会话出现在对应的“最近聊天/最近工作”。
- 导入、导出失败有可读错误，不破坏当前会话。

### 本次实现记录

- 已新增客户端“会话概览”入口，显示 Pi 真实统计、会话分支树及当前叶节点。
- Pi RPC 新增 `navigate_tree`、`import_session`、`export_jsonl`；桌面端只使用脱敏 DTO，不传递会话源文件绝对路径给 Renderer。
- 跳转树节点默认不请求分支摘要，因此不会为跳转额外发起模型调用；跳到用户消息时，会把该消息带回输入框供修改后继续。
- Fork、Clone、导入成功后会重新同步快照，当前会话和“最近聊天/最近工作”列表随之更新。
- HTML 与 JSONL 导出都由 Main Process 打开系统保存对话框；JSONL 导入由系统选择文件对话框发起。
- 导入会话将放入当前活动会话所在的存储范围。导入的工作会话若记录了一个仍存在的工作目录，客户端会同步到该目录；不存在时 Pi 会返回可读错误并保留原会话。

## 阶段 2：Agent 运行控制

### 范围

- 明确选择“立即转向（steer）”或“任务完成后执行（follow-up）”。
- 查看、清空和单项移除等待队列。
- 配置 steering/follow-up 的批处理策略。
- 自动压缩开关、自动重试开关、取消等待中的重试。
- 用户直接执行临时 Bash/PowerShell 命令，并显示流式终端输出。

### 验收标准

- 运行中输入不会再隐式决定队列类型。
- 用户能够解释和控制每个待执行任务。
- 自动重试、压缩、终端执行均可中止，并在时间线显示结果。

### 本次实现记录

- 运行中发送消息不再固定隐式追加到 follow-up 队列；输入框可明确选择“立即转向”或“完成后执行”。
- 输入框展示等待任务数量，可查看 steering/follow-up 的实际队列内容并一键清空。
- 设置页已接入 Pi 的 steering/follow-up 批处理策略、自动上下文压缩和自动重试开关。
- 工作会话采用 Pi 原生 Bash 输入语义：`!<命令>` 执行并纳入模型上下文，`!!<命令>` 执行但排除模型上下文；不再提供重复的桌面端 `/bash` 指令。
- 已新增可展开的直接终端面板、终端中止与自动重试取消控件；剩余：单条队列消息移除，以及终端面板的尺寸拖拽/历史管理。

## 阶段 3：多模态与工件体验

### 范围

- 输入框支持图片附件，按模型能力过滤并通过 Pi RPC `prompt.images` 发送。
- 预览 Tool 返回的图片、音频和文件工件，而不只显示占位文本。
- 统一附件大小、格式、数量限制；Main Process 负责读取与边界校验。
- 扩展 Tool 渲染器，支持常见结构化结果、文件下载和复制。

### 验收标准

- 支持视觉的模型可收到本地图片。
- 媒体结果能安全预览，超大内容被截断且明确提示。

### 本次实现记录

- 输入框支持选择 JPG、PNG、GIF、WebP 图片；最多 4 张、单张最多 6 MB、总计最多 12 MB。
- 图片读取与缓存都在 Main Process。Renderer 仅持有用于缩略图显示的受控预览和附件 ID，发送时由 Main Process 解析 ID 并调用 Pi `prompt.images`。
- 当前模型不支持视觉输入时，附件入口不可用；调用前 Main Process 也会再次校验模型能力。
- Tool 返回的图片与音频会在 Inspector 中安全预览；Base64 超过限制或类型不支持时只显示说明。

## 阶段 4：MCP、Skills、Memory 管理

### 范围

- MCP/Extension：安装、配置、启用/禁用、重载、错误诊断。
- Skills/Prompt Templates：浏览来源、搜索、启用状态、安装或移除 Pi Package。
- Memory：区分上下文文件与语义 Memory；支持查看、配置来源、刷新与清理。
- Project Trust：展示信任状态，提供可信任/撤销入口，并说明生效时机。

### 前置条件

- 先确认 Pi Extension 和 Package 管理的稳定 API；若 Pi 当前只有交互式命令，则新增最小 RPC，不在 Renderer 直接运行包管理命令。
- MCP 状态必须反映 Pi Runtime，不伪造远端服务器在线状态。

### 验收标准

- 用户可从客户端完成一个 Extension/MCP 的配置闭环。
- 密钥不回显、不写入 Renderer 存储，也不进入日志。

### 本次实现记录

- 已接入 Pi Extension 的通知、状态栏文本、Widget 与编辑器文本事件；选择、确认、输入和编辑器对话框维持原有支持。
- 已在 Pi RPC 增加 Package/资源管理接口，并由 Main Process 代理安装、更新、移除和启用/禁用；支持用户级与项目级作用域，项目级操作继续受 Project Trust 约束。
- 资源中心现在展示 Package、Skill、Extension、Prompt 和 Tool。Extension 的 Tool/命令贡献与加载诊断可见，变更后由 Pi Runtime 统一重载。
- 0.3.0 增加在线 Package 商店：主进程从 npm Registry 查询 `pi-package`，展示包类型、下载量、发布时间、npm manifest、依赖与安装脚本风险，并复用 Pi 原生安装 RPC。
- 下载进度、取消、更新检查和项目覆盖的三态继承展示仍留待后续完善；Renderer 不直接执行包管理命令或修改 Pi 设置文件。

## 阶段 5：IDE 工作区

### 范围

- 可编辑代码页：保存、撤销、搜索、文件变更冲突提示。
- Git 状态、Diff 审查、按文件接受或撤销 Agent 变更。
- 可停靠终端面板和命令历史。
- 项目切换记录、最近项目、工作区恢复与多窗口策略。

### 验收标准

- 用户可在不离开客户端的情况下审查、修改、运行并提交项目改动。
- Git 与文件操作始终经过工作区边界校验。

### 本次实现记录

- “项目文件”视图现在使用中央代码编辑器：支持搜索、浏览器原生撤销、还原到打开文件时的内容、`Ctrl/Cmd + S` 保存和未保存状态提示。
- 保存请求只会从 Renderer 发送相对路径、文本和打开时的修改时间；Main Process 再次校验工作区边界、文本大小和磁盘版本。磁盘已发生变化时拒绝保存，避免覆盖外部或 Agent 后续修改。
- Agent 文件变更卡片新增“确认保留”和“撤销本次变更”。撤销前会比对当前文件是否仍是该次工具调用写入的版本；变更被截断或之后已修改时拒绝自动撤销，要求人工处理。
- 中央空编辑器状态显示当前工作区的 Git 分支、领先/落后信息、文件状态及暂存/未暂存 Diff。Git 调用仅由 Main Process 使用无 Shell 的 `git` 子进程执行，Renderer 不能传入命令参数。
- 终端仍然停靠于工作区底部；本次客户端运行期间的最近命令可通过上下方向键或历史标签复用。历史不持久化，避免把可能含密钥的命令写入本地存储。
- 剩余：Git 暂存、提交、分支管理，以及多窗口策略。这些操作会改变用户 Git 状态，后续需单独设计确认与错误恢复流程。
