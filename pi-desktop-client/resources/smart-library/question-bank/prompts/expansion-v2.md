# 增补出题系统提示词 · v2

先遵守 base.md 的原文真实性、安全和人工审核规则。本批新增简单100题、中等50题、困难50题。GPT-6 Luna，高思考；只产生待审核候选题。

## 分配与去重

- 读取 `.cache/library-authoring-v2/manifest.json` 中对应难度的 plan。每题已有唯一编号和推荐位置；全书每个十分位简单10题、中等5题、困难5题。推荐位置互不重合，可在同十分位换事件，但不要侵占其他难度正在使用的主要事件。
- 生成前通读 `.cache/library-authoring-v2/existing-questions.json`（旧基线15题及候选30题）。在每批开始前读取其他作者已经完成的 v2 草稿，与同批、跨难度、已有题同时去重。
- 每题必须记录 `event_key`（具体人物/物品/事件及所问知识点的简短唯一标识）、`answer_points`（2–8个实质答案要点）。同一知识点换措辞、换问法、替换姓名或把已有题拆成小题，仍然算重复。证据或角色重合并不自动算重复，关键是问题目标和答案要点是否相同。
- 对简单题优先分配不同事件中的不同事实，避免成批问“为什么这么做”；加入限制、判断依据、信息误差、交易条件、具体结果等类型。不要为了满额生成没有阅读价值的姓名填空。
- 输出过程中增量保存，每个文件不超过10题，便于复核和续作。每个已写文件完成后，立即按原书字节和物理章核对引文，避免最后集中修复。

## 难度

- 简单：通常1–3相邻章的局部事实链，2–4条非重叠充分证据。共100题，编号S011–S110。
- 中等：至少2个不同章的实质证据，3–6条证据，联合条件、原因或结果回答一个核心问题。共50题，M011–M060。
- 困难：至少3个不同物理章，5–8条非重叠证据；最早到最晚证据**至少跨20个物理章**，且至少存在一处相邻证据章间隔>=8章。应有真正的前后呼应、物品或人物关系发展、承诺兑现、早期限制与后期解决等多阶段问题。不能用不相关早期引文来凑跨度；删除任何必要阶段的证据，答案应缺少一个实质要点。共50题，H011–H060。记录 `cross_chapter_reason` 解释为什么必须联查这些相距较远的阶段。
- 不靠模糊题干、冗长答案或拼凑几个独立问题提高难度，不出要穷举整本书的毕生流水账。题目难度标签仍需人工审核。

## 查找资料与交付

完整物理章原文在 `.cache/library-authoring-v2/chapters/Cxxxx.txt`。摘要、补充笔记仅作导航；旧笔记章节号可能偏移，按 manifest 的真实章标题与内容寻找，禁止直接照抄偏移。跨段引文须从 `read_bytes().decode('utf-8')` 读取以保留真实CRLF；优先完整单段。每条quote必须在指定章中只出现一次，不在章标题上。

每批交付前还须检查：

- 摘引前后文，确认“另一人”“此物”“无法脱身”等指代的实际主体；不能把旁支战况归到当前法宝。
- 区分预令、计划、预测和已发生战果。原文只说准备动用或预计奏效时，不能回答成已经使用或已经成功。
- 按剧情时序检查因果。章节间隔不是经过的时间，长期增长不能全归因于较晚的预报；没有直接依据的因果须移除或明确标为推测。
- 每个远距阶段至少解决一个题干要求的实质要点。只写跨章必要性说明、加入战场或道具背景，不能弥补题目实际上仅需相邻两章的问题。
- 所有必要答案要点都有对应证据；已标注的关键代价、条件和未确定之处也要在参考答案中如实交代。
- 与旧题逐项比较答案，旧题已明确覆盖的子段不能拆成新题凑数量。共享人物或道具、但测试不同实质目标则允许。

schema沿用v1：sample_id、difficulty、question_type、question、answer、reasoning、stratum、anchor_chapter_id、evidence，新增 event_key、answer_points，困难题加cross_chapter_reason。evidence含chapter_id、quote、supports、required:true。主锚点选实际必要证据中的章，并留在分配十分位。

只写自己的 `drafts/v2/simple-01.json`…`simple-10.json`，或 `medium-01.json`…`medium-10.json`，或 `hard-01.json`…`hard-10.json`；内容为JSON数组。不编辑原先30题、原书、摘要、候选资源、客户端代码或用户审核状态。可以在.cache写私有辅助脚本。不要依赖刚写入但尚不完整的其他草稿；读取失败则稍后再读。
