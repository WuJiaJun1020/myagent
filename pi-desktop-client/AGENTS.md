# 前端界面注意事项

- 以现有 Agent 工作区为视觉基准，各模块保持统一、简洁、紧凑的风格；优先复用公共组件和样式。
- 颜色使用现有主题变量，字体、字号、圆角和间距沿用公共规范；标题与正文层级清楚，不靠缩小字号解决拥挤。
- 浅色和深色都要有清晰的悬浮、选中、禁用及焦点反馈，尤其注意浅色侧栏的悬浮高亮。
- 提示框、下拉选项、菜单和删除确认使用应用内统一样式，避免原生 title、系统确认框与界面混搭。
- 精简重复标题、按钮和说明，避免大面积空白及层层套卡片；保留必要的错误与操作后果提示。
- 长内容优先用弹窗查看或编辑，固定标题与操作区、内部滚动；浮层对齐自然，不越界、不遮挡关键操作。
- 适配窄窗口、大字号和长文本，避免横向溢出、控件挤压；输入工具栏保持单行，代码审查保持左右布局。
- 交互及时、直接且可逆：开关能再次关闭，悬浮预览随当前条目更新；不丢失草稿、未保存编辑或用户设置。
- 修改后实际检查显示与交互，不只看代码；至少确认浅深色、窄布局、悬浮、展开与关闭。
- 只调整用户要求的范围，不擅自增加功能或改变业务流程，不修改 pi-agent 核心。
- 新增模型、运行环境、缓存或测试产物时，保持 Vite 仅扫描应用入口，并将运行数据排除出监听；修改加载链路后用独立冷缓存检查首次模块切换，不能只测热更新后的速度。

详细规范按需参考 [主题说明](docs/WORKSPACE_THEME_GUIDE.md) 和 [设计规划](docs/CLIENT_UI_REDESIGN_PLAN.md)，以最新用户要求为准。

# 代码与测试约定

- 客户端测试、验收脚本、样本和测试替身统一放 `tests/`，按 `unit`、`node`、`integration`、`e2e`、`python`、`helpers`、`fixtures` 分类；不要散落在 `src/` 或 `scripts/`。上游 `pi-agent` 不随客户端整理迁移。
- 测试报告、截图、数据库和临时构建放 `.cache/` 或临时目录，保持 Git 忽略；测试必须自行准备样本，不能依赖上次测试缓存、个人文件或真实服务。真实模型验收单独执行。
- 修改相关逻辑后运行对应测试与 `typecheck`；迁移目录或改公共基础设施后执行 `npm test`，涉及原生存储再执行 `test:integration`。各运行器与命令见 [测试说明](tests/README.md)。
- Worker 通信使用统一客户端及操作类型映射，明确参数、返回值、超时和退出清理；通信超时或强制取消时先结束旧 Worker，再允许重建，写操作不自动重试；业务错误单独返回，保留检查点和正常取消逻辑。
- 区分开发目录、安装资源目录与用户数据目录；模型脚本随应用发布，GPU Python 环境和权重存放外部并允许配置路径，不硬编码个人路径，不将权重、缓存或普通测试打入安装包。
